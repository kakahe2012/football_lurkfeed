## 1. 工作流概览

```
football-content-factory (skill)
        │
        ▼  生成 *_eng.html（KC v3 模板）

        │

        │
        ▼  /admin/queue 一键通过 → 上线
football.lurkfeed.com
```

## 2. KC v3 → 网站字段自动映射

后台导入器会从每个 HTML 文件 **零配置** 抽取下面这些字段：

| 网站字段 | 来源（按优先级） |
|----------|------------------|
| `title` | `<meta property="og:title">` → `<h1 class="article-title">` → `<title>` |
| `slug` | 从 `title` 自动 `slugify`（已存在则加 4 位随机后缀） |
| `intro_hook` | `<p class="article-lead">` → `<meta name="description">` → 正文前 160 字 |
| `hero_image` | `<meta property="og:image">` → 正文第一张 `<img>` |
| `tags` | `<meta name="keywords">` + `<meta property="article:tag">`（去重、最多 8 个） |
| `emotion_type` | `<meta name="article:section">` / `.article-category` / `.hero-badge` 智能映射（见下表） |
| `seo_title` / `seo_description` | `og:title` / `og:description` / `meta description` |
| `read_time_minutes` | `.article-meta` 里 "X min read" → 否则按 200 wpm 估算 |
| `published_at` | `<meta property="article:published_time">` → `Article` JSON-LD `datePublished` → 当前时间 |

### KC 分类 → 站点情绪映射

| KC `CONTENT_CATEGORY` / 关键 tag | 站点 `emotion_type` |
|----------------------------------|---------------------|
| `Prediction/Odds`、`prediction`、`odds`、`fantasy` | **hype** 🔥 |
| `Retrospective`、`heartbreak`、`scandal`、`controversial` | **heartbreak** 💔 |
| `Luxury`、`Fashion`、`mbappe/ronaldo/...`、`celebrity`、`cars`、`mansions` | **icons** 👑 |
| `Drama`、`Gossip`、`wags`、`relationships`、`debate`、`transfer` | **secrets** 🤫 |
| `Guide`、`for-new-fans`、`explain-meme`、`trivia` | **easy_football** ⚽ |
| `Meme`、`Culture`、`fan-experience`、`watch-party` | **culture** 🌍 |

**自动消毒会做这些事**：

- 移除 `<script>` / `<iframe>` / `<style>` / `onclick=` 等 XSS 向量。
- 移除 KC 模板自带的 `nav` / `footer` / `read-more`（指向 kickoffculture.com 的外站 CTA）/ `internal-link-card`（站内链接对我们站无效）。
- 保留 `takeaways` / `fact-box` / `pull-quote` / `ranked-list` / `faq-section` / `source-note` 这些**结构化语义 class**，前端会按 KC 风格但配合本站配色重新渲染。

## 3. 在后台批量上架（手动 GUI 方式）

1. 打开 **http://localhost:3000/admin/publish**（生产为 `https://football.lurkfeed.com/admin/publish`）。
2. 输入 `ADMIN_SECRET` 登录（生产环境必须改成强随机值）。
3. **「① 导入 HTML 文章」** 区域：
   - 「选择文件」可一次选多个 `.html`。
   - **「选择文件夹」** 可整个 `articles/20260601/` 拖入，浏览器会读取里面所有 `.html`。
   - 默认状态：**待审核**（推荐）。也可直接选「直接发布」一键上线。
4. 提交后会显示每篇导入结果：标题、slug、自动识别的情绪、tags。
5. 「② 批量发布现有文章」可勾选草稿/待审文章，**批量发布或拒绝**。

文件大小限制：单文件 600 KB，单次 ≤ 100 篇。

## 5. 首页排序权重（Hot Score）

首页瀑布流不再是简单的"按发布时间倒序"，而是 **Hacker News 风格的时间衰减热度算法**：

```
score = (share_count × 8 + view_count × 1 + ctr_score × 200 + 1)
        ÷ (age_hours + 4) ^ 1.5
```

特性：

- **Share 权重最高**（×8）：分享是最强的"值得朋友看"信号。
- **gravity = 1.5**：发布 24h 后热度衰减到原来的 ~1/8，新内容能持续上首页。
- **offset = 4**：避免新发布瞬间排名爆炸，给数据收集留缓冲。

调用方式：

```
GET /api/feed?page=0          # 默认 hot
GET /api/feed?page=0&sort=newest  # 按时间倒序
```

`/admin/articles` 详情页仍按发布时间倒序，方便编辑维护。
「Trending」侧栏沿用最近 3 天 view_count 排序。

## 5.1 封面 / 正文图兜底（真实场景文化图库）

当 `hero_image` 或正文 `<img>` 为空、本地路径（如 `/Users/...`）、或加载失败时，站点会替换为 **30 张自托管的真实足球场景照片**（球场、看台、球员、球迷、球衣、庆祝等），存放在 `public/culture/photos/`。

| 层级 | 行为 |
|------|------|
| 1 | 文章原图 |
| 2 | 按 `slug` 哈希选定的一张文化实景图 |
| 3 | 池中另一张实景图（仍非抽象占位） |

- 同一篇文章始终映射到同一张主图；刷新不会随机乱跳。
- 导入 / 读库 / 展示三层兜底：`resolveHeroImage`、`fixContentImageUrls`、`FallbackImage` + 正文 `img` 的 `error` 监听。

维护：

```bash
npm run culture:fetch          # 从 Unsplash 重新下载 30 张（见 scripts/culture-photo-manifest.json）
npm run import:articles [dir] # 刷新 seed 并修正坏链
```

清单与授权说明：`public/culture/PHOTOS.md`。代码：`src/lib/media/culture-images.ts`。

## 6. 部署上线后的额外步骤

1. **环境变量** `NEXT_PUBLIC_SITE_URL=https://football.lurkfeed.com`（已是 `.env.example` 默认值）。
2. **`ADMIN_SECRET` 必须是强随机值**：`openssl rand -hex 24` → 写入 Vercel 环境变量。生产若仍是默认值，后台会被自动锁定（503）。
3. Vercel 域名绑定 `football.lurkfeed.com`，并在 Cloudflare DNS 加 CNAME。
4. Supabase 执行 `supabase/migrations/001_*.sql` → `002_*.sql` → `003_*.sql`。
5. 上架第一批文章前，建议先在生产页 `/admin/publish` 上传 1 篇测试一下，确认样式没跑偏。

## 7. 排错

| 现象 | 排查 |
|------|------|
| 导入后情绪识别为 culture（兜底）| HTML 缺少 `meta article:section` / `.hero-badge` / 关键 tag。可在后台「文章管理 → 详情」手动改。 |
| 标签是空的 | KC 文件没填 `meta keywords`，后台详情页可手动加。 |
| 首图缺失（变成文化图）| KC 未设 `og:image` 或路径为本地盘符；会自动用文化图库。若希望真实封面，生成时填 `{{COVER_IMAGE_URL}}` 或可公网访问的 URL。 |
| 正文图裂图 | 导入 HTML 含本机路径；重新导入或依赖运行时兜底。 |
| 后台登录页显示「服务未配置」| 生产环境 `ADMIN_SECRET` 未改。前往 Vercel 设置。 |
| Supabase 连不上时导入「成功」但数据未持久化 | 后台返回 `persisted: false`。检查 `SUPABASE_SERVICE_ROLE_KEY`。|

## 8. 字段对照速查

```text
KC v3 HTML                        →   posts table
─────────────────────────────────────────────────────
<title>                           →   seo_title (<= 70 chars)
og:title                          →   title
og:description / meta description →   seo_description / intro_hook
og:image                          →   hero_image
meta name="keywords"              →   tags (slugified)
meta name="article:section"       →   emotion_type (mapped)
.hero-badge / .article-category   →   emotion_type (fallback)
.article-lead                     →   intro_hook (preferred)
<article class="article-wrap">    →   content (sanitized)
JSON-LD Article datePublished     →   published_at
.article-meta "X min read"        →   read_time_minutes
.read-more / .internal-link-card  →   discarded (external CTA)
.article-tags chips               →   discarded (we render our own)
```
